значения, номера страниц.  Текст мануалов не цитируется.

Сокращения в таблице: `inov.c` = `lcec_inovance.c`, `class.c` =

`documentation/inovance.md`.  Номера строк даны для v1.46, если не
указано иное.

Важное архитектурное замечание: класс cia402 не реализует машину
состояний CiA 402.  Controlword/statusword передаются как есть
(`class.c:233,544` и `class.c:279,489`); логика переходов, fault reset и
quick stop живёт во внешнем HAL-компоненте `hal-cia402`
(`documentation/cia402.md`, раздел «How to use»).  Поэтому пункты про
биты 6040/6041 проверены как «проходит ли бит без искажений» плюс
требования привода, которые должен соблюдать внешний компонент.

## 3. Предложения правок драйвера

### P1

1. **Обрабатывать modParams на v1.46.**  Перенести `handle_modparams()`
   из di-errcode (`inov.c:57-79`, вызов `inov.c:127`) в v1.46.  Сейчас
   все cia402-modParams объявлены, но молча игнорируются (п. 59).  Пока
   это не сделано, `inov.md` должен прямо говорить, что modParams не
   работают.
2. **Исправить правило Hgg-nn в `inov.md`** (п. 62): «субиндекс = nn + 1,
   где nn — десятичный номер параметра; результат записывается в hex»,
   добавить пример H02-10 → 0x2002:0B и H0E-01 → 0x200E:02 (IS p.284;
   CG p.104).
3. **Убрать или уточнить «Supports EoE»** в `inov.md:30` (п. 66).
   Мануалы заявляют только CoE (CG p.33; RU p.447).  Если EoE видно в
   SII, так и написать.
4. **Цикл связи: документация плюс предупреждение при init.**  В
   `lcec_inovance_init` выводить `RTAPI_MSG_WARN`, если `sync0Cycle`
   меньше 125000 нс или не кратен 125000 нс (EE13.0 / Er.E13; CG p.201,
   RU p.222, IS p.362).  Для типа IS620N дополнительно предупреждать,
   если цикл < 1 мс (для CSP/PP/HM, IS p.186).  Набросок: сравнение
   `dc->sync0Cycle % 125000`, ветвление по `slave->pid`.
5. **Раздел про EEPROM в `inov.md`** (п. 63–64): SDO-записи по
   умолчанию сохраняются в EEPROM (SV660N 200E:02, IS620N 200C:0E,
   умолч. 3).  Описать риск для часто меняемых SDO-пинов (`enableHM` и
   прочие `enable*` SDO-пины, P2-5) и рекомендацию: значение 0 для
   рантайм-записей и постоянная конфигурация через `<sdoConfig>`.

### P2

1. **60F4 со знаком** (п. 58): `PDO_PIN_TYPE_actual_following_error` →
   HAL_S32, `PDO_SIGN_...` → S в `opt.h`.  Это правка класса, она
   затронет все драйверы.  Проверить, не опирается ли кто-то на U32.
2. **Опциональный 203F** (п. 50–51): modParam, например
   `enableVendorErrorCode`, добавляет 0x203F:00/32 в 1A00 и пин
   `srv-vendor-error-code` (U32).  Укладывается в лимит: 9 записей, 27
   байт.  Можно сделать локально в `lcec_inovance.c` через
   `lcec_syncs_add_pdo_entry` после `lcec_cia402_add_input_sync`, не
   трогая класс.
3. **modParam сохранения в EEPROM**, например `eepromSaveMode` (0..3).
   Пишет 200E:02 для SV660N и 200C:0E для IS620N; индекс выбирается по
   `slave->pid`.  Сам параметр тоже пишется в EEPROM (CG p.199), но
   одна запись на старт допустима.
4. **modParam режима синхронизации** `syncMode` (0..2) и
   `syncErrorWindow`: SV660N 200E:20 / 200E:21, IS620N 200C:2C /
   200C:2D (п. 22–23).  200E:20 вступает только после перезапуска
   питания (RU p.585), это надо задокументировать.
5. **SDO-пины класса: не писать при первом цикле.**  `_old`
   инициализируется нулём (`class.c:530`), а пин — значением,
   прочитанным из привода (`class.c:469-470`).  Поэтому на первом
   цикле OP уходит лишняя SDO-запись того же значения, то есть ещё одна
   запись в EEPROM.  Набросок: после `SET_OPTIONAL_DEFAULTS`
   присваивать `data->X_old = *data->X`.
6. **Опциональные 60E0/60E1** (п. 55): новые опции класса
   (`enable_torque_limits`), RxPDO 7 записей / 17 байт.  Единицы 0.1 %.
7. **Мониторинг H0B по SDO** (только чтение, без износа EEPROM):
   опциональные пины с медленным опросом через `ecrt_sdo_request`
   (раз в N циклов).  Кандидаты: 200B:1B напряжение шины, 200B:1C
   температура модуля, 200B:0D средняя нагрузка, 200B:19 ток фазы,
   200B:01 скорость (CG p.185-193; IS p.351-356).  Индексы у IS620N и
   SV660N совпадают по конспекту, единицы — проверить по типу привода.
8. **Ошибки в ratio-modParams класса** (п. 53): возвращать код ошибки
   `lcec_write_sdo*_modparam` (`class.c:793-842`).  В `inov.md`
   перечислить неприменимые к Inovance modParams: 605B, 6007, 60F2,
   607B, 608F, 6090, 6092, 6093, а для IS620N ещё
   `enableFollowingErrorTimeout` (6066).
9. **Документировать 60FD** (п. 46–49): таблица `din-*` → бит → сигнал
   для SV660N и для IS620N при 200C:2A = 2 и 0/1/3; пометить
   `din-interlock` как неиспользуемый.

### P3

1. Алиас типа `SV660N` (та же VID/PID и init) при сохранении `SV660`
   для совместимости (п. 5).  Проверить, не ломает ли дубликат PID
   автогенерацию конфигурации.
2. При init прочитать 2002:01 и предупредить, если не 9 (п. 65).
3. Диагностические пины: 200E:19 (потери SYNC), 1C32:20 (sync error),
   200E:24 (AL status code) — медленный опрос SDO (п. 25).
4. Чтение журнала аварий (H0B-33.., 200B:22..2C) по требованию — пин
   выбора записи плюс выходные пины (CG p.139, p.189-190).
5. modParam `homeCalcMode` → 60E6 (п. 43).
6. Документация: тормоз и принудительная реакция 605A/605C/605E при
   включённом тормозе (п. 69); `enableDigitalOutput` / `dout-brake` не
   соответствуют 60FE Inovance (п. 70); правила смены режимов (п. 31);
   единицы 0.1 % для 6071/6072/6077.
7. Документация: рекомендация по `<dcConf>` sync0Shift при EE08/EE15 —
   фаза SYNC относительно прихода кадра, канал осциллографа «SYNC and
   IRQ phase» (SP p.53-56).

## 4. Открытые вопросы / проверить на стенде

1. **1C32:05 / 1C33:05 на SV660N**: 125000 или 250000 нс? Мануал даёт
   оба значения (RU p.350 против p.557).  Прочитать SDO на обоих
   приводах.  Проверить, доходит ли SV660N до OP при цикле 125 и 250
   мкс.
2. **Пишется ли маппинг PDO в EEPROM** при 200E:02 = 3: после записи
   1600/1A00 выключить питание и прочитать 1600:00 / 1A00:00 до
   конфигурации мастером.  Если маппинг сохраняется, каждый старт
   LinuxCNC тратит ресурс EEPROM.
3. **Умолчание 1A00:07** (60FD 16 или 32 бита) на заводском
   SV660N — расхождение RU p.555 и p.342.
4. **Product code** у всех имеющихся экземпляров SV660N (0x000C010D или
   0x000C0108, п. 3).
5. **IS620N в CSP с циклом < 1 мс** (IS p.186): работает ли на деле
   и на каком цикле стоит стенд.
6. **200C:2A на стендовом IS620N**: от него зависит смысл `din-*`.
   После переключения 0 ↔ 2 проверить, какие биты 60FD меняются.
7. **Фронт fault reset на IS620N** (противоречие IS p.182): работает
   ли сброс по фронту 0→1, как в SV660N.
8. **Режим синхронизации по умолчанию** на SV660N (200E:20 = 1 по CG
   p.201): возникает ли EE15.0 под нагрузкой LinuxCNC; стабильнее ли
   режим 2.
9. **EoE в SII**: что показывает `ethercat slaves -v` в списке mailbox
   protocols (п. 66).
10. **Хоминг через SDO** (di-errcode): видны ли в 6041 bit 12/13/15
    при 6060 = 6; сколько SDO-записей уходит за цикл хоминга (п. 44).
11. **Abort-коды** при записи 605B, 607B и 608F (п. 36, 53): убедиться,
    что init падает с понятным сообщением.
12. **60F4 на шине**: проверить, что при отрицательной ошибке пин
    показывает ~4.29e9 (подтверждение п. 58).
13. **Состав 1600 по умолчанию**: CG p.48 ({6040, 6060, 60B8}) против
    CG p.31 / RU p.336 ({6040, 607A, 60B8}).  Для драйвера это не важно,
    но полезно для generic-конфигов.
