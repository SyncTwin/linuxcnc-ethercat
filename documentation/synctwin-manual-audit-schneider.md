# Schneider Lexium 28E: сверка драйвера с документацией производителя

Сверка драйвера `schneider` (ветка `synctwin/v1.46`) с документацией Schneider Electric. Код драйвера здесь не меняется — только факты и предложения.

**Источники:**
- **E** — «Lexium 28E and BCH2 Servo Drive System, User Guide» EIO0000002454, 10/2018. Документ написан под прошивку LXM28E V1.75. Номер страницы PDF совпадает с печатным.
- **A16** — «LXM28A and BCH2 Product manual» 0198441114054 V2.1, 04/2016 (CANopen-вариант, то же семейство).
- **A22** — «Lexium 28A User Guide» EIO0000002305.05, 2022 (CANopen-вариант, прошивка V1.78).

Документы A приведены там, где мануал E молчит. Нумерация параметров и вендорских объектов у семейства общая. CANopen-специфичное помечено отдельно.

**Сверялись:**
- `src/devices/lcec_schneider.c`;
- `src/lcec.h`;
- `documentation/DEVICES.md`;
- общий класс `src/devices/lcec_class_cia402.c` / `.h` / `_opt.h`.

**Статусы:**
- **совпадает** — драйвер и документация согласуются;
- **нет** — в драйвере нет того, что описано в документации, или наоборот;
- **расходится** — драйвер или его комментарии утверждают иное, чем документация.

**Контекст.** Предыдущие PR драйвера Schneider в апстрим закрыты: на стенде привод не дошёл до OP. Поэтому в первую очередь проверялось всё, что мешает переходам PreOp → SafeOp → Op: PDO-конфигурация, DC, обязательные SDO при старте.

## Почему привод мог не дойти до OP — гипотезы по документации

Порядок — от наиболее вероятной:

1. **Нет DC/SYNC0 при режиме CSP.** Заводской 0x6060 = 8 (CSP). CSP и IP описаны как синхронные режимы с периодом 0x60C2 и стартом по SYNC (E 289, 299). Драйвер DC не задаёт (`lcec_schneider.c:47-48`). Если в XML не было `<dcConf>`, привод получает только SM-синхронизацию. Отказ в SafeOp → Op с ошибкой синхронизации — ожидаемый исход: N.ERR одиночная вспышка (E 306).
2. **0x60C2 не совпадает с циклом мастера.** Требование — E 289. У родственного 28A заводское значение 2 мс (A16 393). Цикл LinuxCNC обычно 1 мс. Драйвер 0x60C2 не пишет.
3. **P3-08 = 0 («протокол не выбран»)** — заводское значение (E 242). Мануал не говорит прямо, что это блокирует процессные данные. Но других объяснений для этого параметра в LXM28E нет. Проверить: прочитать 0x4308.
4. **Слишком ранний Enable после старта синхронизации** — AL3E1 (A16 278). Это уже не «не доходит до OP», а «падает в Fault сразу после OP».
5. **Смена ESM при включённом каскаде** — AL401 (E 317). Проявляется при перезапуске LinuxCNC без выключения привода.
6. PDO-маппинг драйвера по мануалу корректен (п. 7–10): маловероятная причина, если не включались modParams из п. 10.

## Что проверить на стенде (нужен привод с мотором)
- `ethercat upload` 0x4308, 0x60C2:01/02, 0x6060, 0x6502, 0x608F:01, 0x6092:01, 0x1C12/0x1C13, 0x1600/0x1A00 :00…:0A.
- Есть ли в приводе 0x1C32 и 0x1C33 (в OD мануала их нет).
- AL-статус (`ethercat slaves -v`) и LED N.ERR при неудачном SafeOp → Op с `<dcConf assignActivate="300" sync0Cycle="*1">` и без него.
- После OP: 0x603F, P0-01 (0x4001), P4-00 (0x4400).
